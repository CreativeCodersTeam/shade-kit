## Benefit

A team can use any of the three target agents for the same feature, even mixed within one team, because they all run the same skills against the same engine and the same `.shadekit/` data. This is part of the v1 success criterion: "a team can take a feature from `new` to `finish` with any of the three target agents".

## Scope

### In scope

- The research that answers concept open question 5, written down as a research note.
- `integrations install --agent copilot` and `--agent codex`, and their part of `integrations update` and `version`.
- Agent-specific adaptations of the content from package 06, limited to what the research shows is needed.
- The instruction file Copilot reads, as a possible addition to package 02's managed section.

### Out of scope

- New skill behaviour. This package makes existing skills run on two more agents; it adds no features.
- Hooks and MCP configuration (as in package 07).
- Enabling a disabled plugin, removing an integration (`integrations uninstall`), and reading the agents' configuration files (Copilot `~/.copilot/`, Codex `config.toml`); the engine reads the state only through the agents' list commands. **Decided** on 2026-11-15 (package 08, Gate 2).

### Step 2: install and update

#### Content source

- `integrations install --agent copilot|codex` installs the same content as for Claude Code at user level, as a plugin through the agent's own CLI, from the same marketplace `CreativeCodersTeam/shade-kit` at the same ref. Both agents have a plugin mechanism, so no content is written into a user directory. **Decided** (concept §3.1); the plugin route for both agents **Decided** on 2026-11-15 (package 08, Gate 2; research note decision 2). **Implemented** (`CopilotCliIntegration`, `CodexCliIntegration`).
- One skill source for all three agents: the skills under `skills/` and the manifests `.claude-plugin/marketplace.json` and `.claude-plugin/plugin.json` serve Claude Code, Copilot, and Codex unchanged. There is no install-time transformation and no second copy, so the engine still contains and copies no content. **Decided** on 2026-11-15 (package 08, Gate 2), replacing the **Proposed** transformation at install time and the **Open** question how Copilot and Codex get the content from the tag (both since 2026-11-13). The marketplace name `creativecoders-shade-kit` and the plugin id `shade-kit@creativecoders-shade-kit` are the same for every agent. **Implemented** (`ShadeKitPlugin.Name`, `.MarketplaceName`, `.Id`; `ClaudeCodeIntegration.MarketplaceName` and `.PluginId` point to them; `ShadeKitPluginTests`). The FP08-AC4 guard checks the single source (Acceptance criteria).
- **FACT** (research note §3.1, §4.1): Copilot looks up `marketplace.json` and `plugin.json` at several places before `.claude-plugin/`, Codex looks for `.agents/plugins/marketplace.json` and `.codex-plugin/plugin.json` first; none of these exists in this repository, so both read the `.claude-plugin/` manifests. An agent-specific manifest at one of those places would take precedence; the guard refuses it.
- Rule of package 07 extended: the plugin root is the repository root, so every plugin component that an agent finds at its default location ships to every user. For Copilot these are also `agents/`, `skills/`, `hooks.json` or `hooks/hooks.json`, `.mcp.json` or `.github/mcp.json`, and `lsp.json` or `.github/lsp.json` (**FACT**, GitHub Docs Copilot CLI plugin reference, read on 2026-11-15). So a developer-only `.github/mcp.json` or `.github/lsp.json` must not be added to this repository either. **Decided** on 2026-11-15 (package 08 implementation; documentation only, no guard test, as in 07). **FACT** (`ls` on 2026-11-15): none of them exists.

#### Version pin and state

- The version pin (tag `v<engine version>`, `main` for a prerelease engine and for a release engine whose tag does not exist, the release-tag check, `SHADE_KIT_MARKETPLACE_SOURCE`), the state read from the agent instead of an engine-owned record, and the order of `install` and `update` work as in package 07, for every agent. **Decided** on 2026-11-15 (package 08, Gate 2), replacing **Proposed** (2026-11-13). **Implemented** (`IntegrationService` is unchanged; it resolves the source once per run for all agents; `IntegrationServiceTests.InstallAsync_ClaudeCopilotAndCodexDetected_InstallsAllInRegistrationOrderFromOneSource`, `IntegrationServiceTests.UpdateAsync_ThreeAgentsWithCopilotNotInstalled_UpdatesOthersFromSourceResolvedOnce`, `IntegrationsMultiAgentEndToEndTests.IntegrationsUpdate_PrereleaseEngineWithThreeAgents_UpdatesAllFromMainWithOneWarning`).
- `kitVersion` and `ref` of a result come from the marketplace source, as for Claude Code (`IntegrationResult.ForShadeKitPlugin`, `MarketplaceSource.GetKitVersion`; `IntegrationResultTests`).

#### Shared marketplace decision

- The decision what an install or update does with the marketplace `creativecoders-shade-kit` is the same for every agent: missing → add; same GitHub repository (case-insensitive) and same ref (case-sensitive), or the same directory → keep; same repository, other ref → switch; same repository and a ref the agent does not report (`AgentMarketplace.IsRefReported` `false`, only Codex) → verify, the agent checks the ref itself; another repository, kind, or directory → conflict (exit code 53), nothing changed. It was extracted from `ClaudeCodeIntegration` without a change of behaviour; the result `Verify` was added on 2026-11-18 (review finding STD-05), so that Codex no longer receives a `Switch` it ignores, without a change of behaviour. **Decided** on 2026-11-15 (package 08, Gate 2, option B: one command sequence per agent, the decision and the result construction shared). **Implemented** (`MarketplaceChangeResolver`, `MarketplaceChange`, `AgentMarketplace`, `AgentMarketplaceSourceKind`; each agent maps its own marketplace record with `ClaudeMarketplace.ToAgentMarketplace`, `CopilotMarketplace.ToAgentMarketplace`, `CodexMarketplace.ToAgentMarketplace`; `MarketplaceChangeResolverTests`, `AgentMarketplaceTests`, `ClaudeMarketplaceTests`, `CopilotMarketplaceTests`, `CodexMarketplaceTests`). `ClaudeCodeIntegrationTests` pass unchanged, except one assertion on the renamed `IntegrationConflictException.ResolveCommands`.
- `IntegrationConflictException.ResolveCommands` is a list of commands in the order to run them, because Copilot needs two (exit code 53 below); it replaces the single `ResolveCommand` of package 07. **Implemented** (`IntegrationExceptionTests.IntegrationConflictException_ResolveCommandsChangedAfterConstruction_KeepsCommandsInOrder`).
- Registration: the integrations are singletons, added with `TryAddEnumerable` in the order Claude Code → Copilot → Codex, which is the order in which `install` and `update` run them. **Implemented** (`ShadeKitCoreServiceCollectionExtensions.AddShadeKitCore`; `ShadeKitCoreServiceCollectionExtensionsTests.AddShadeKitCore_CalledTwice_RegistersEachAgentIntegrationOnceAsSingletonInRunOrder`).

#### How the engine runs `copilot` and `codex`

- Process rules as for `claude` (07): found in an absolute directory of the `PATH`, started by absolute path through the process helpers, process tree killed on cancellation (exit code 130), `NO_COLOR=1`, the user's home directory as working directory (`UserWorkingDirectory`), never the repository. **Decided** on 2026-11-15 (package 08, Gate 2). **Implemented** (`CopilotExecutableLocator`, `CopilotCommandRunner`, `CodexExecutableLocator`, `CodexCommandRunner`, on `PathExecutableLocator` and `ExternalToolRunner`; `CopilotCommandRunnerTests`, `CodexCommandRunnerTests`). **Unverified:** that the `copilot plugin` and `codex plugin` commands evaluate `NO_COLOR`.
- The list commands parse the whole stdout as one JSON value (Copilot an array, Codex an object); a stray line makes `install` and `update` fail with 52, and gives the warning `agent-unavailable` in `version`. **Implemented** (`CopilotJsonOutputReader`, `CodexJsonOutputReader`; `CopilotPluginCliTests.ListMarketplacesAsync_StrayLineBeforeArray_ThrowsCopilotCommandFailedException`, `CodexPluginCliTests.ListMarketplacesAsync_StrayLineAfterObject_ThrowsCodexCommandFailedException`). A failing command's message is the last non-empty line of stderr, or of stdout when stderr has none (Codex prints no JSON on failure, **FACT** from the source, D5).
- The engine uses no CLI flag that the research did not confirm. **Decided** on 2026-11-15 (package 08, Gate 2).
- Windows: for `copilot` and `codex` only, each absolute `PATH` directory is checked for `<name>.exe`, then for `<name>.cmd`, before the next directory; `<name>.ps1` is not supported. Claude Code stays `claude.exe` only (07). **Decided** on 2026-11-15 (package 08, Gate 2; research note decision 4). **Implemented** (`PathExecutableSearch` with an ordered list of Windows names; `PathExecutableSearchWindowsNamesTests`, `CopilotExecutableLocatorTests.FindCopilotExecutable_WindowsDirectoryContainsExeAndCmd_ReturnsExe`, `CopilotExecutableLocatorTests.FindCopilotExecutable_WindowsDirectoryContainsOnlyNpmShims_ReturnsCmd`, `CopilotExecutableLocatorTests.FindCopilotExecutable_WindowsPathContainsOnlyPowerShellShim_ReturnsNull`, and the same `CodexExecutableLocatorTests`).
- A `.cmd` shim (the npm installation) is run through `cmd.exe`, a documented deviation from the "no shell" rule of the process helpers, decided by the user after an objection (`cmd.exe` re-parses its command line, the argument-injection class of BatBadBut / CVE-2024-24576). **Decided** on 2026-11-15 (package 08, Gate 2). **Implemented** (`CmdShimCommandLine`, `ExternalProcessStart`, `ExternalToolRunner.CreateProcessStart`; the opt-in is `ExternalTool.CmdShims` (a `CmdShimPolicy` with the refused-argument exception factory `CreateRefusedArgumentException`), set only by `CopilotCommandRunner.Tool` and `CodexCommandRunner.Tool`):
  - `%ComSpec%` must be a fully qualified path whose file name is `cmd.exe`; otherwise the run fails before anything starts with the tool's unavailable exception (52). The command line is `/d /s /c ""<shim path>" <arguments>"`, passed verbatim; an argument that is empty or contains whitespace is quoted, with its trailing backslashes doubled.
  - The shim path and every argument are checked against the refused characters `"`, `%`, `!`, `^`, `&`, `|`, `<`, `>`, `(`, `)`, CR, LF, and NUL; one of them is refused, not escaped, and fails with the tool's command-failed exception (52), naming the path or the argument position and the character. The path is checked with the same full list as the arguments (D4, strict). **Decided** on 2026-11-15 (after Task 3).
  - Tests: `CmdShimCommandLineTests`, `ExternalToolRunnerTests.CreateProcessStart_CmdShimWithValidComSpec_StartsComSpecWithVerbatimCommandLine`, `ExternalToolRunnerTests.CreateProcessStart_CmdShimWithRefusedArgument_ThrowsTheToolsCommandFailedException`, `ExternalToolRunnerTests.CreateProcessStart_CmdShimPathWithRefusedCharacter_ThrowsTheToolsCommandFailedException`, `ExternalToolRunnerTests.CreateProcessStart_CmdShimWithUnusableComSpec_ThrowsTheToolsUnavailableException`, `ExternalToolRunnerTests.CreateProcessStart_CmdWithToolWithoutOptIn_StartsItDirectlyAsBefore`.
  - **Unverified:** the Windows behaviour itself (not run on Windows); that npm puts `copilot.cmd` and `codex.cmd` on the `PATH`; whether `cmd.exe` or Node map Unicode lookalikes such as the fullwidth `＆` and `％` (Windows "best-fit" mapping), which are not refused (Open points).

#### `integrations install [--agent claude|copilot|codex] [--json]`

- `--agent` takes `claude`, `copilot`, or `codex`, case-insensitive; one value. An unknown id or a bare `--agent` ends with exit code 2: `Invalid arguments: 'gemini' is not a supported agent for --agent (supported: claude, copilot, codex). Run 'shade-kit integrations install --help' for usage.` The help text: `The agent to install for: 'claude', 'copilot', or 'codex'; without it, every detected agent`. **Decided** on 2026-11-15 (package 08, Gate 2). **Implemented** (`AgentOptionConverter.SupportedAgentIds`, `IntegrationsInstallCommandOptions`; `AgentOptionConverterTests.Convert_SupportedIdInAnyCase_ReturnsIdOfSupportedAgent`, `IntegrationsInstallCommandOptionsTests.Agent_HelpText_NamesEverySupportedAgent`, `IntegrationsCommandsEndToEndTests`).
- Without `--agent`, every detected agent is installed, in registration order. `--agent copilot` or `--agent codex` without its CLI ends with 51 before the release-tag check (`EnsureAvailable`, as in 07). **Implemented** (`AgentIntegrationBase<TPlugin>.EnsureAvailable` with `CopilotCliIntegration.CreateNotFoundException` and `CodexCliIntegration.CreateNotFoundException`; `IntegrationsMultiAgentEndToEndTests.IntegrationsInstall_NamedAgentNotOnPath_Exits51BeforeReleaseTagCheck`, `IntegrationsMultiAgentEndToEndTests.IntegrationsInstall_AllThreeAgentsDetected_InstallsInRegistrationOrder`).
- Copilot counts the plugin as installed only when `copilot plugin list --json` lists the name `shade-kit` with the marketplace `creativecoders-shade-kit`; Codex only when the `installed` list of `codex plugin list --json` has that name and marketplace with `installed` `true`. A plugin of the same name from another marketplace or a direct install does not count.

##### Copilot steps

The change commands of Copilot (`plugin install`, `plugin update`, `plugin uninstall`, `plugin marketplace add`, `update`, `remove`) have no `--json`: success is exit code 0, and the engine then reads the state again with `copilot plugin list --json` and `copilot plugin marketplace list --json`. **Decided** on 2026-11-15 (package 08, Gate 2, decision 5a; the switch D2 after Task 1). **Implemented** (`CopilotCliIntegration`, `CopilotPluginCli`; `CopilotCliIntegrationTests`, `CopilotPluginCliTests`):

- marketplace missing: `plugin list --json`, `plugin marketplace list --json`, `plugin marketplace add <source>`, `plugin list --json`, then `plugin install shade-kit@creativecoders-shade-kit` or `plugin update shade-kit@creativecoders-shade-kit`, then `plugin list --json`;
- marketplace kept: `plugin list --json`, `plugin marketplace list --json`, `plugin marketplace update creativecoders-shade-kit` (it re-fetches the catalog, because a marketplace that follows a branch keeps the commit of its last fetch), then `plugin update` (or `plugin install` when not installed), then `plugin list --json`;
- switch (same repository, other ref): `plugin list --json`, `plugin marketplace list --json`, `plugin uninstall shade-kit@creativecoders-shade-kit` (only if installed), `plugin marketplace remove creativecoders-shade-kit` without `--force`, `plugin marketplace add <source>`, `plugin install`, `plugin list --json`. The uninstall comes first because Copilot refuses `marketplace remove` while plugins of the marketplace are installed (**FACT**, GitHub Docs plugin reference). **Decided** on 2026-11-15 (D2), replacing the **Proposed** order of the research note; `--force` was the rejected one-step alternative.
- `<source>` is the source text of 07: `CreativeCodersTeam/shade-kit#v0.8.0`, `owner/repo`, or an absolute directory.
- A plugin that is not listed after its install or update fails with 52.
- A disabled plugin stays disabled; the result reports `enabled` `false`.
- **Unverified:** all commands and output shapes (not run); the shape of `copilot plugin marketplace list --json`, which the GitHub Docs do not document (`CopilotPluginCli` reads the source as an object or as a kind string with `repo`, `ref`, `path` beside it, and the kinds `github`, `directory`, `local`; any other kind is a conflict); that `plugin update`, `uninstall`, and `enable` take `shade-kit@creativecoders-shade-kit`; that a bare tag works after `#`.

##### Codex steps

Every Codex command takes `--json`; there is no `plugin update` and no enable command. **Decided** on 2026-11-15 (package 08, Gate 2, decision 5b; D1 after Task 1, D5 after Task 5). **Implemented** (`CodexCliIntegration`, `CodexPluginCli`; `CodexCliIntegrationTests`, `CodexPluginCliTests`):

- `marketplace add` is `codex plugin marketplace add <owner/repo> --ref <ref> --json` for a GitHub source (`<owner/repo> --json` without a ref), `codex plugin marketplace add <path> --json` for a directory.
- Codex reports a marketplace source only as `{ sourceType, source }`, without the ref (**FACT**, `codex-rs/cli/src/plugin_cmd.rs` `JsonMarketplaceSource`, tag `rust-v0.169.0`). So `CodexMarketplace.ToAgentMarketplace` marks the ref as not reported (`IsRefReported` `false`), the resolver returns `Verify` for a Git marketplace with the repository of the source, and the engine runs the add as a check (D5):
  - `alreadyAdded: true` → kept: `codex plugin marketplace upgrade creativecoders-shade-kit --json`, then `codex plugin add shade-kit@creativecoders-shade-kit --json`;
  - exit code 0 with `alreadyAdded: false` → only `codex plugin add`;
  - a non-zero exit code → switch: `codex plugin remove shade-kit@creativecoders-shade-kit --json` (only if installed), `codex plugin marketplace remove creativecoders-shade-kit --json`, `codex plugin marketplace add … --json`, `codex plugin add … --json`.
- A kept directory marketplace (`Keep`) runs only `codex plugin add`, no `marketplace upgrade` (D1): Codex refuses to upgrade a marketplace that is not a Git marketplace (**FACT**, `codex-rs/core-plugins/src/manager.rs`), and `plugin add` replaces the cache entry with a new copy (**FACT**, `codex-rs/core-plugins/src/store.rs`).
- marketplace missing: `plugin list --json`, `plugin marketplace list --json`, `plugin marketplace add … --json`, `plugin add … --json`, `plugin list --json`.
- Every run ends with `plugin list --json`; a plugin that is not listed as installed fails with 52. `plugin add` always enables the plugin, also a disabled one (**FACT**, `install_resolved_plugin`), so the result reports the state Codex lists afterwards.
- A directory source that contains `#` is refused with 52 before `codex` runs, because Codex splits a source at its last `#` into source and ref (**FACT**). **Implemented** (`CodexPluginCliTests.AddMarketplaceAsync_DirectoryWithHash_ThrowsCodexCommandFailedWithoutRunning`).
- Tests of the sequences: `CodexCliIntegrationTests.InstallAsync_KeptGitMarketplaceWithInstalledPlugin_ChecksSourceUpgradesAddsPluginAndReturnsUpdated`, `InstallAsync_GitMarketplaceAddedByCheck_AddsPluginWithoutUpgradeOrRemoval`, `InstallAsync_CheckAddFailsWithAnyNonZeroExitCode_SwitchesMarketplace`, `InstallAsync_KeptDirectoryMarketplace_AddsPluginWithoutMarketplaceAddOrUpgrade`, `InstallAsync_GitMarketplaceWithOtherSourceAndInstalledPlugin_RemovesPluginAndMarketplaceAndAddsBoth`, and the end-to-end tests `IntegrationsMultiAgentEndToEndTests.IntegrationsUpdate_CodexMarketplaceWithSameRef_UpgradesMarketplaceAndAddsPluginAgain`, `IntegrationsUpdate_CodexMarketplaceWithOtherRef_SwitchesMarketplaceAndAddsPlugin`, `IntegrationsInstall_CodexDirectoryOverrideKept_AddsPluginAgainWithoutMarketplaceUpgrade`.
- **Known risk** (D5): a check add that fails for another reason (network, proxy, login) counts as "other source", so the switch removes the plugin and the marketplace, and its add fails too, with `IntegrationIncompleteException`. Codex is then left without the skills until a new run with a working connection repairs it. The incomplete error of Codex names this possible cause after the repair hint (`AgentPresentations.CodexIncompleteNote`: `Codex counts a failed check of the marketplace as another source, so the switch may also have followed a network, proxy, or login failure; restore the connection first.`). **Decided** on 2026-11-18 (review of the branch, finding SPEC-05), keeping the switch of D5. **Implemented** (`CliErrorMapper.CreateIntegrationIncompleteError`; `CliErrorMapperTests.Map_IntegrationIncompleteWithCodexCommandFailure_KeepsExitCode52AndAddsRepairHint`, `Map_IntegrationIncompleteOfCodexWithUnmappedCause_AddsRepairHintAndNetworkCause`, `Map_IntegrationRunFailedWithIncompleteCodexSwitch_AddsNetworkCauseBeforeCompletedAgents`, `AgentPresentationsTests.Find_KnownAgent_ReturnsEntryWithItsIncompleteNote`).
- Known limit (D5): `previousKitVersion` is set only on a confirmed keep (then it is the kit version of the source).
- **Unverified:** none of the commands has been run; that a tag works as `--ref`; that the commands work without a signed-in account; the exit codes.

##### Outcome and failures (both agents)

- Outcome: `installed` when the plugin was not installed before the run, otherwise always `updated`, never `current`. Neither agent reports "up to date" for a plugin (Copilot's change commands print nothing, Codex has no update command), so an unchanged plugin cannot be told from a refreshed one. **Decided** on 2026-11-15 (package 08, Gate 2). **Implemented** (`CopilotCliIntegrationTests.InstallAsync_KeptMarketplaceAndPluginInstalled_RefreshesMarketplaceThenUpdatesAndReturnsUpdated`, `CodexCliIntegrationTests.UpdateAsync_KeptGitMarketplace_UpgradesAddsPluginAndReturnsUpdated`).
- `previousKitVersion`: Copilot from the ref of the marketplace before the run, when the plugin was installed (as Claude Code); Codex only on a confirmed keep (D5).
- No rollback. A failure after the plugin was uninstalled or removed, or after the old marketplace was removed, is `IntegrationIncompleteException` with the repair hint of 07; a cancellation from the first removal on is `IntegrationSwitchCanceledException` (130, repair hint). **Implemented** (`CopilotCliIntegrationTests.InstallAsync_MarketplaceRemoveFailsAfterUninstall_ThrowsIntegrationIncompleteWithCause`, `CopilotCliIntegrationTests.InstallAsync_CanceledWhilePluginIsUninstalled_ThrowsSwitchCanceledWithoutRemoval`, `CodexCliIntegrationTests.InstallAsync_MarketplaceRemoveFailsAfterPluginRemove_ThrowsIntegrationIncompleteWithCause`, `CodexCliIntegrationTests.InstallAsync_CanceledWhilePluginIsRemoved_ThrowsSwitchCanceledWithoutMarketplaceRemoval`, `IntegrationsMultiAgentEndToEndTests.IntegrationsUpdate_CodexFailsAfterSwitchStartedAndCopilotSucceeded_AddsRepairHint`). The new exceptions derive from `ExternalToolException` (`CopilotUnavailableException` → `CopilotNotFoundException`, `CopilotCommandFailedException`, and the same for Codex), so a failure after another agent was done names the completed integrations (`IntegrationRunFailedException`, 07; `IntegrationsMultiAgentEndToEndTests.IntegrationsInstall_SecondAgentFailsAfterFirstSucceeded_Exits52NamingCompletedIntegration`, `IntegrationServiceTests.InstallAsync_CodexFailsAfterClaudeAndCopilot_ThrowsRunFailedWithBothResultsInOrder`).
- Like Claude Code, the commands need no git repository and write nothing into one (FP07-AC5 also for these agents: `IntegrationsMultiAgentEndToEndTests.IntegrationsInstallAndUpdate_CopilotAndCodexInGitRepository_CreateOrChangeNoFileInIt`).

#### `integrations update [--json]`

- Updates every installed agent with the steps of `install`, in registration order; an agent whose plugin is not installed is not touched and resolves no source (07). **Implemented** (`AgentIntegrationBase<TPlugin>.UpdateAsync`, shared by `CopilotCliIntegration` and `CodexCliIntegration`; `IntegrationsMultiAgentEndToEndTests.IntegrationsUpdate_SeveralAgentsInstalledAndOneNot_UpdatesInstalledOnesInRegistrationOrder`, `IntegrationsUpdate_CopilotMarketplaceKept_RefreshesMarketplaceAndUpdatesPlugin`).

#### Output of `install` and `update`

- JSON unchanged (07): the same `data` shape, `pluginId` `shade-kit@creativecoders-shade-kit` for every agent. **Decided** on 2026-11-15 (package 08, Gate 2).
- Plain output, one line per agent as in 07.
